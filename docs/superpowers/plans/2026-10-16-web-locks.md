# Web Locks Monorepo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and publish-ready `@web-locks/core` and `@web-locks/react`, three Pages-hosted sites (landing, React demo, vanilla demo), and the CI/release workflows, in the existing Vite+ monorepo.

**Architecture:** Core owns all stateful logic as small framework-agnostic stores (`getState`/`subscribe`); React hooks are thin `useSyncExternalStore` wrappers. Every function takes an optional `locks` (default `navigator.locks`) so a shared in-memory fake `LockManager` can drive all tests.

**Tech Stack:** TypeScript, Vite+ 1.3.0 (`vp pack`/tsdown, Vitest, Oxlint, Oxfmt), pnpm workspaces, `bumpp`; apps add React, Tailwind CSS v4, lucide, sonner.

**Spec:** `docs/superpowers/specs/2026-10-16-web-locks-design.md`

## Global Constraints

- `@web-locks/core` has zero dependencies. `@web-locks/react` has only the `react` peer (`>=18`) and `@web-locks/core: workspace:*`. Third-party packages are allowed only in the private apps.
- ESM-only output with `.d.ts` (as scaffolded). License is `Apache-2.0` everywhere.
- Nothing touches `navigator`/`document` at import time (SSR-safe).
- Repo URL: `https://github.com/web-locks/web-locks`. URLs: `https://web-locks.github.io/` (website, base `/`), `/react/` (react-example), `/vanilla/` (core-example). `base` applies to production builds only.
- Lock-hook callbacks live in refs; changing them never re-elects.
- Commit after every task, ending the message with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Gate before the final task: `vp check`, `vp run -r test`, `vp run -r build` (the root `ready` script).
- Unknown command forms (`vp test run <file>`) are confirmed in Task 1 Step 6; use whatever works there throughout.

**Deviation from spec (decision):** the shared fake `LockManager` lives in a new private workspace package `tools/fake-locks` (the workspace already globs `tools/*`), so core and react tests import one implementation. It is never published.

## Review Focus

1. Locks API absent (SSR, insecure context, old Safari): every API reports `"unsupported"` and never throws.
2. React StrictMode mount → unmount → mount: exactly one lock held afterward, none leaked.
3. Unmount/`stop()` while still queued or while the grant is in flight: the lock is aborted or released immediately, never held by a dead owner.
4. Another tab calls `steal`: the displaced holder leaves `"held"`, with no unhandled rejection.
5. `onPromoted`/`onDemoted` throwing: error goes to `onError`, leadership still resigns cleanly.

### Task 4: core `acquireLock`

**Files:** Create `packages/core/src/lock.ts`, `packages/core/tests/lock.test.ts`.

**Interfaces:** Consumes `resolveLocks`. Produces `type LockHandle = {readonly name: string; release(): Promise<void>}`; `type AcquireOptions = {mode?: LockMode; ifAvailable?: boolean; steal?: boolean; signal?: AbortSignal; locks?: LocksLike; onLost?: () => void}`; `acquireLock(name: string, options?: AcquireOptions): Promise<LockHandle | null>`. Resolves `null` if unsupported or `ifAvailable` loses. The lock is held by a pending promise resolved by `release()`. `release()` is idempotent and resolves once the request callback has finished.
