Why Web Locks

  • One active tab

    Exactly one tab holds a named lock at a time. It runs the sync worker, the socket or the singleton client while the rest wait in standby.

  • No polling

    Waiting tabs are queued by the browser and are promoted the moment the lock frees up. No timers, heartbeats or storage events.

  • Survives crashes

    The browser releases a lock when its tab closes, reloads or crashes, so a dead leader can never leave the others stuck.

Browser support

The Web Locks API works in Chrome and Edge 69+, Firefox 96+ and Safari 15.4+. Page freeze and resume events are available in Chromium only. Where the API is missing, the helpers report an unsupported state instead of throwing.
